# 招聘能力展示与验证设计

用户用途：面向移动机器人定位/SLAM、机器人软件工程岗位展示 FAST-Lio2-个人研究版。传感器为 MID-360，场景为室内/园区。用户已授权自主调研、实施、验证和公开上传；本轮沿用该授权。

## 选择与边界

公开招聘样本正在按公司官网或其 ATS 核验，记录链接、访问时间、原文短摘录、学历/经验与技能要求。样本不是整个招聘市场的统计，不以作品替代学历、工作年限、工作许可或实机经历。

本轮选择两个与既有数据和代码直接相关的交付：C++17 离线体素处理，以及配置化回归检查。回环/地图定位需要额外算法、参考与场景验证；实机部署需要目标机器人，暂不将其写成已经掌握或交付。

## C++17 体素处理

- 输入为有限的 N×4 XYZI，坐标单位米，体素原点为零，`floor(x / size)` 分箱，支持负坐标。
- C++ 用哈希表累加双精度坐标与强度，再按整数 XYZ 体素键排序，输出 float32 质心与 int64 占据点数。使用传统体素质心处理，不称为新 SLAM 算法。
- Python 包装保留双精度输入，调用显式构建的共享库；库缺失或输入无效须报错，不自动回退并冒充 C++ 结果。
- C ABI 的内存由同一库分配/释放，异常不跨过 ABI，失败不返回半成品。空输入、NaN/Inf、非正体素、整数范围及异常清理有测试。
- `scripts/process_map.py` 增加可选 `--voxel-backend cpp` 和 `--voxel-library`；默认仍为 NumPy。两个实现有完全相同的体素原点、分箱和输出顺序；允许浮点累加的末位差异，并报告数值差异。
- CMake/CTest 不依赖 ROS、Eigen 或 PCL；CI 编译 Release 并执行测试，另用 ASan/UBSan 检查 C++ 生命周期与无效输入。

## 性能实验

从既有 Outdoor01 全图读取并仅做既有重力旋转，一次导出 float64 XYZI 输入；源地图 SHA256 与变换写入记录。比较 0.50、0.20、0.10 m 三档，两实现各三轮，以交错顺序运行独立子进程。

主计时仅覆盖体素调用，输入加载和结果保存另列；资源指标为每个工作进程整个生命周期的 Linux `ru_maxrss`，包含解释器、输入、处理及验证，不解释为算法独占内存。保留每轮耗时、输入/输出点数、点数守恒、占据点数一致性、坐标和强度最大差异、编译器/选项、CPU 与源文件哈希。重复是同一地图的软件计时，不是独立场景样本；不做定位精度或在线 FAST-LIO2 提速推论。

实施修正：最小复现实验发现 Linux `ru_maxrss` 会保留 fork/exec 前父进程的内存峰值，导致小工作进程读数被抬高。最终图表采用 `/proc/self/status` 的 `VmHWM`（exec 后地址空间），另存原始 `ru_maxrss` 作为诊断项。两者均不是算法独占内存。首轮受此影响的数据留在本地，修正后重新运行完整三档三轮，不把不同口径混入最终汇总。

## 回归检查

读取 `evaluate_engineering.py` 已导出的两组 `metrics.json`、`run_summary.json` 与显式 JSON 容差配置。先验证字段/类型/有限数值与内部计数，再检查可比性：序列、输入台账哈希、回放速率、时长、初始化帧、DDS/计时/资源口径、参考哈希、配对和对齐规则。

可比时检查完整运行、进程退出、缺帧/记录错误、队列容量、RSS 预算、核心 p95 和位置参考 RMSE 的绝对及相对上限。阈值为示例工程容差，非行业标准，也不是预注册实验。报告输入文件与配置哈希、每项实测/上限、状态与局限；不重算原始轨迹和计时文件，不把摘要检查冒充原始测量认证。

CLI 返回：0=通过，1=未通过容差或完整性，2=数据无效或不可比；不可比时不出性能优劣结论。NaN、布尔值冒充数字、重复 JSON 键、缺字段与阈值拼错均不能静默通过。当前 TCP 旧格式不自动迁移，支持本轮 `recording` / `surf03` 格式。
