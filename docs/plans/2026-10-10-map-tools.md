# 地图记录与展示实施计划

用户已授权自主实施、联网核查和验证后公开推送。目标是 MID-360 移动机器人工程实践与求职展示。保留 Outdoor01 原始实验、原始地图和运行中的原节点。

## 实施范围

1. 从 PCL、CloudCompare、Potree、ROS 2 等官方资料核查体素、离群点过滤、局部表面拟合、EDL、多分辨率加载及有界后台记录设计。记录实际访问的链接和采用范围。
2. 新增 NumPy/SciPy 离线工具：严格解析 binary PCD、重力对齐、体素质心、统计离群点过滤、受位移与平面性限制的局部平面投影。后者准确命名，不声称实现完整 PCL MLS。
3. 从已有真实地图生成固定区域、相机、尺度、色标的处理对照，以及高度、强度、单色和 EDL 展示。发布轻量派生三维数据、参数、源哈希和处理统计。
4. 新增浏览器点云查看器：本地依赖、多分辨率空间分块、点数预算、颜色模式、EDL、轨迹、预设视角、截图；在实际浏览器检查交互、资源预算和错误处理。
5. 新增独立 ROS 2 地图记录器：后台分块写盘、有界队列、显式丢帧/写盘错误、原子索引和恢复。单元测试覆盖队列满、写入失败、异常退出恢复及消息格式。
6. 增加关闭上游历史地图和路径缓存的部署配置。在独立 domain 与构建副本完整回放 Outdoor01，报告 mapping 与记录进程的 RSS、CPU、记录完整性及原始位置参考误差。只声明本次实测结果。
7. 更新 README、复现命令、结果图和方法来源，执行数值测试、浏览器验证、独立审查、基线完整性及发布检查，合并到 main 并推送 GitHub，发布 Pages 查看器。

## 分工与文件边界

- 主任务：离线处理、数据导出、真实回放、图表、整合与发布。
- 查看器任务：`docs/viewer/` 内 UI、JS、样式和第三方资源；不改 `docs/viewer/data/`。
- 地图记录任务：`scripts/map_recorder.py`、`scripts/map_writer.py`、相关独立测试和记录器文档；不改算法或公共 README。

## 查看器数据接口

`docs/viewer/data/manifest.json`，相对 URL 均相对 manifest 文件。`schema_version=1`，`bounds={min:[x,y,z],max:[x,y,z]}`，单位米，Z 向上。`color_ranges={height:[min,max],intensity:[min,max]}` 固定显示色域。`source` 保留点数、SHA256 和旋转说明。`trajectory={url:"trajectory.json",count:N}` 指向 `{positions:[[x,y,z],...],timestamps:[...]}`，为仅重力对齐的原始估计轨迹。

`variants` 数组元素：`{id,label,description,point_count,bounds,lods:[...]}`。每级 LOD：`{id,voxel_size_m,point_count,tiles:[...]}`；每块：`{id,url,point_count,bounds,sha256,byte_size}`。tile 为 gzip 压缩的小端 float32 交错 `[x,y,z,intensity]`，每点 16 字节；没有隐含头部。每一 LOD 为独立覆盖，不能把粗细层叠加计点。浏览器在读取前后检查长度，按可见空间块加载，及时释放不再使用的 GPU 数据，并确保实际加载点数符合点预算。

## 验收与声明范围

- 数值：非有限点/截断 PCD 被明确处理；体素顺序确定；过滤点数守恒；投影位移有上限且边缘不盲目平滑。
- 工程：记录持久化数、丢弃数、错误、队列上限均可核对；恢复不把未完成块计入成功。回放只停止本轮创建的进程。
- 展示：使用真实扫描派生数据；固定相机下检查处理差异；色标有单位；轨迹不平滑为精度结果。页面可在普通静态 HTTP 服务与 GitHub Pages 使用。
- 评估：核心处理计时不冒充端到端延迟；峰值采样值与总资源都明确；RTK 杆臂和 GT 姿态限制保持；每配置单轮不声称统计显著性。
- 发布：不上传原始 bag/285 MB PCD、凭据、机器特有环境；原始基线文件 SHA256 不变。
